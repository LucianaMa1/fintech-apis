API Catalogue — 多维标注分类体系

核心设计原则
01
多维度标注（Faceted），不用单一树形，任意组合筛选
02
维度正交，每个维度描述一个独立特征，互不重叠
03
标注可机器读取，既支持人类浏览，也支持程序查询
六个核心标注维度
⬡
D1 · 能力域（Domain）
这个 API 解决什么问题领域
AI & ML 通信 金融支付 地图地理 媒体处理 身份认证 数据存储 IoT & 硬件
◈
D2 · 交互模式（Interaction）
调用方和 API 如何通信
REST GraphQL WebSocket gRPC Webhook SSE / 流式 消息队列
▣
D3 · 资源类型（Resource）
API 操作的核心对象是什么
文本 图像 音视频 结构化数据 事件流 文件 / 二进制 物理设备
◎
D4 · 商业模式（Business）
如何定价和获取访问权
免费 / 开源 Freemium 按量计费 订阅制 企业授权 数据交换
◆
D5 · 成熟度（Maturity）
API 的稳定性和生命周期阶段
GA 稳定 Beta Experimental Deprecated
⬡
D6 · 合规 & 数据属性（Compliance）
数据敏感性与监管要求
PII 涉及 金融合规 医疗 HIPAA 仅限特定地区 无限制
标注实例 — 三个真实 API
OpenAI Chat Completions API
openai.com · 生成式 AI 对话
D1: AI & ML D2: REST · SSE流式 D3: 文本 · 图像 D4: 按量计费 D5: GA D6: 无限制（输入内容由用户负责）
Stripe Payment Intents API
stripe.com · 支付处理
D1: 金融支付 D2: REST · Webhook D3: 结构化数据（交易） D4: 交易手续费 D5: GA D6: PCI-DSS · 金融合规
Google Maps Directions API
maps.googleapis.com · 地理寻路
D1: 地图地理 D2: REST D3: 结构化数据（路线） D4: Freemium · 按量计费 D5: GA D6: 含位置 PII · 部分地区受限
补充元数据字段（机器可读）
除六个分类维度外，每条记录还附带以下字段：
auth_method（API Key / OAuth2 / mTLS）· rate_limit_tier（低 / 中 / 高并发）· latency_profile（<100ms / <1s / 异步）· sdk_support（官方 SDK 语言列表）· openapi_spec_url（机器可读规格文档链接）· sla_uptime（承诺 SLA 百分比）
